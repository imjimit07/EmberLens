# UI audit 001 - 2026-11-15

Scope: the existing EmberLens static frontend and the proposed PeakChart React component. No UI changes were made during this audit.

## Findings

1. HIGH - R-02 Copywriting: em dashes remain in user-facing page text and in dynamically rendered content. Examples include the document title in `frontend/index.html:9`, the comparison-panel description at `frontend/index.html:123`, and several UI strings in `frontend/app.js`. Replace them with punctuation appropriate to each sentence before treating the interface as compliant.

2. HIGH - R-35 Verify before delivery: the UI has not been exercised in a browser for this audit. Python compilation and JavaScript syntax checks pass, but FastAPI is absent from the active Python environment, so the application could not be launched and its navigation, form actions, loading states, charts, mobile menu, and keyboard flows could not be verified.

3. MEDIUM - R-08 Button arrows: arrows are repeated as decoration in summary metric labels and quick-start cards, for example `frontend/index.html:40-48`. These arrows do not consistently express navigation or state. Keep only arrows that explain a destination or action.

4. LOW - R-15 CTA specificity: the hero link uses "Explore observations" in `frontend/index.html:36`. It names the content but not the action. Use a direct action that describes the destination, such as "Set study filters", if the existing link continues to scroll to `#filters`.

## PeakChart integration readiness

The component cannot be copied into this project as-is. EmberLens is a FastAPI application that serves `frontend/index.html`, `frontend/styles.css`, and `frontend/app.js` directly. It has no React runtime, TypeScript configuration, Tailwind setup, package manifest, bundler, or `components/ui` directory.

The supplied component itself has no npm-only visual dependency. It uses React, browser canvas APIs, `IntersectionObserver`, and `requestAnimationFrame`. Its `@/components/ui/peak-chart` import assumes a TypeScript alias from `@` to the application source directory.

For a Vite migration, use `web/src/components/ui/peak-chart.tsx`, not a top-level `/components/ui` directory. This follows shadcn's conventional `src/components/ui` alias target and makes the supplied `@/components/ui/peak-chart` import resolve predictably. Creating that directory in the current static frontend alone would leave the component unused because the browser cannot execute TSX.

## Setup path, not executed

Keep the FastAPI backend and place the React application in a separate `web` directory. The official Vite and shadcn guidance supports this arrangement:

```bash
mkdir web
cd web
pnpm create vite@latest . -- --template react-ts
pnpm add tailwindcss @tailwindcss/vite
pnpm add -D @types/node
pnpm dlx shadcn@latest init
```

Configure Tailwind's Vite plugin and the `@` alias in `vite.config.ts`, add matching `baseUrl` and `paths` entries to `tsconfig.json` and `tsconfig.app.json`, then put `@import "tailwindcss";` in the app's global stylesheet. The shadcn initializer creates `components.json` and installs its required dependencies. After that, copy the supplied component to `web/src/components/ui/peak-chart.tsx`.

Before adding it to a screen, decide which EmberLens API series supplies its `data`, `labels`, `value`, and period-change handler. The closest data sources are the existing activity and anomaly endpoints, but the current component's Weekly, Monthly, and Yearly selections are demo periods and do not yet match those API contracts.
